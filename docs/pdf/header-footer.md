# Header and Footer

You can add a header and/or a footer to PDFs generated by the HTML, URL and Markdown builders.

They are rendered by Chrome's native `headerTemplate` / `footerTemplate` feature, the same mechanism Gotenberg uses.
That mechanism has limitations, listed below.

> [!WARNING]
> Every header or footer template must be a full HTML document:
> ```html
><!DOCTYPE html>
><html lang="en">
>  <head>
>    <meta charset="utf-8" />
>    <style>body { font-size: 10px; margin: 0 1cm; }</style>
>  </head>
>  <body>
>    <!-- Your code goes here -->
>  </body>
></html>
> ```

## Things to know

> [!IMPORTANT]
> **The header and footer are drawn inside the page margins.** With no top or bottom margin, they are invisible, or
> covered by the content. Set margins that are large enough:
> ```php
> ->marginTop(2, Unit::Centimeters)->marginBottom(2, Unit::Centimeters)
> ```

- **Page numbers**: Chrome fills elements that have these classes:
  `pageNumber`, `totalPages`, `date`, `title` (the document `<title>`), `url`.
  ```html
  Page <span class="pageNumber"></span> / <span class="totalPages"></span>
  ```
- **Isolated rendering**: the header and footer do **not** inherit the main document's CSS, fonts or JavaScript. Put
  the styles inline, in the template's own `<style>` block.
- **Small default font**: Chrome renders them with a tiny default font size. Always set `font-size` explicitly.
- **Limited CSS**: no external stylesheets, no web fonts loaded by URL, no JavaScript. `background-color` is only
  printed when you add `-webkit-print-color-adjust: exact;`. The body has a default padding you may want to reset.
- **Assets become data URIs**: Chrome cannot load files in header and footer templates. When you use
  `chrome_pdf_asset()` / `chrome_pdf_font_face()` in a header or footer Twig template, or reference an asset added
  with `assets()` from a header or footer, the bundle inlines the file as a `data:` URI (base64). Keep these files
  small, such as a logo or one font subset.
- **Only one given**: if you set only a header, the footer is left empty (and the other way round). Chrome's default
  date/title/URL line is never printed.
- **PDF only.** Screenshot builders have no `header()` / `footer()` methods (Chrome cannot add them to screenshots).

## Twig file

```php
namespace App\Controller;

use Daif\ChromePdfBundle\ChromePdfInterface;
use Daif\ChromePdfBundle\Enumeration\Unit;
use Symfony\Component\HttpFoundation\Response;

class YourController
{
    public function yourControllerMethod(ChromePdfInterface $chromePdf): Response
    {
        return $chromePdf
            ->html()
            ->content('content.html.twig', ['my_var' => 'value'])
            ->header('header.html.twig', ['my_var' => 'value'])
            ->footer('footer.html.twig', ['my_var' => 'value'])
            ->marginTop(2.5, Unit::Centimeters)
            ->marginBottom(2, Unit::Centimeters)
            ->generate()
            ->stream()
        ;
    }
}
```

`header.html.twig` with a logo (inlined automatically as a `data:` URI):

```twig
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="utf-8"/>
    <style>
        body { margin: 0 1cm; font-size: 9px; font-family: Arial, sans-serif; -webkit-print-color-adjust: exact; }
        img { height: 1cm; }
    </style>
</head>
<body>
    <img src="{{ chrome_pdf_asset('img/logo.png') }}" alt="Logo"/>
    <span class="title"></span>
</body>
</html>
```

## HTML file

> [!WARNING]
> By default, HTML files are fetched from the assets folder of your application.
> For more information about path resolution, see the [assets documentation](../assets.md).

```php
return $chromePdf
    ->html()
    ->headerFile('header.html')
    ->contentFile('content.html')
    ->footerFile('footer.html')
    ->margins(1, 1, 0.5, 0.5)   // inches
    ->generate()
    ->stream()
;
```

Relative paths work as well:

```php
return $chromePdf
    ->html()
    ->headerFile('../templates/html/header.html')
    ->contentFile('../templates/html/content.html')
    ->footerFile('../templates/html/footer.html')
    ->generate()
    ->stream()
;
```

## Raw HTML

```php
return $chromePdf
    ->html()
    ->content('content.html.twig')
    ->footerRaw('<!DOCTYPE html><html><body style="font-size:9px;text-align:center;width:100%">'
        .'Page <span class="pageNumber"></span> / <span class="totalPages"></span></body></html>')
    ->marginBottom(1.5, Unit::Centimeters)
    ->generate()
    ->stream()
;
```

## URL builder

The URL builder accepts the same header and footer methods. The page itself comes from the URL, and the header and
footer come from your templates:

```php
return $chromePdf->url()
    ->url('https://example.com/report')
    ->footer('footer.html.twig')
    ->marginBottom(2, Unit::Centimeters)
    ->generate()
    ->stream()
;
```
